Why the G1 loopback can replay old audio

crates/driver/src/loopback.rs clears each frame once it's read, so stale audio shouldn't leak out. That only holds for frames somebody reads. Frames written while nobody reads stay in the buffer, and a reader that joins later can hear them a full wrap later (up to ~1.36 s at 48 kHz).

1 · The buffer is indexed by sample time

The write for time T always happens before the read for T, so nothing needs to be synchronised. The question is what's in the slot when the reader gets to a time that was never written.

2 · Step through it

audio written, not read yet left over: the reader already passed it, so it's never cleared B hears the live mix B hears silence B hears audio replayed from one wrap ago

Scaled down: 16 slots stand in for 65 536 frames, and one tick is one slot's worth of frames. The reader trails the writer by 2 slots.

3 · What happens, in order

  1. App A plays to Spool, and nobody reads the input. WriteMix fills every slot. Nothing is ever read, so nothing is cleared. That's fine as long as no one is listening.
  2. App B opens Spool's input. IO is already running (io_clients goes 1 → 2), so the clear_loopback() in start_io doesn't run. B starts reading at the current input time. The slots just behind it (amber) still hold audio nobody read.
  3. App A stops. With no client playing, there's nothing to write (assuming the HAL skips WriteMix then, which is likely). B keeps reading past the last frame written.
  4. B reaches the amber slots. Each holds A's audio from exactly one wrap earlier. read() returns it, so B hears that span again, then silence.

HAL overloads leave the same kind of hole on a smaller scale: a skipped cycle isn't written, so its slot still holds the previous wrap. The ring tap fills such gaps with silence; the loopback doesn't.

4 · The fix

Remember how far the output has been written, and return silence for any input time outside the last capacity's worth of writes. BlackHole guards its input the same way, with its last output sample time.

pub struct Loopback {
    channels: usize,
    samples: Box<[AtomicU32]>,
    written_until: AtomicU64, // f64 bits: end of the latest WriteMix
}

// write(t, samples): store frames as now, then
self.written_until.store((t + frames as f64).to_bits(), Release);

// read(t, out): per frame at time ft
let end = f64::from_bits(self.written_until.load(Acquire));
let fresh = ft < end && ft >= end - CAPACITY_FRAMES as f64;
let bits = slot.swap(0, Relaxed);          // still clear what we pass
*v = if fresh { f32::from_bits(bits) } else { 0.0 };

Optionally, write_mix can also zero a skipped span (as the ring's gap fill does), which covers the overload case. A fake-host regression test: write, read nothing, stop writing, read one capacity later, and expect silence.
